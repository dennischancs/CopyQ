# SPEC — 手机端意图与验收标准

> **文档类型：权威事实源（仅限手机端行为）**
> 冲突时，手机端行为以本文件为准。WebDAV 配置包的格式、错误码和桌面规则仍以仓库根目录的 [SPEC.md](../SPEC.md) 为准。本文件只引用那些编号，不另写一套。
> `mobile/prd.md`、`mobile/dev-plan.md`、`mobile/TASKS.md`、`mobile/todo.md` 不另写「假如…那么…」。

## 0. 一句话说明

让 Android 和 iOS 上的 CopyQ 用和电脑端同一套标志、同一套主题颜色、同一份 WebDAV 配置包，管住用户自己的文字剪贴板历史。

**当前状态**：意图已冻结，2026-10-17。测试还没写，手机工程还没建。冻结不等于移植完成。

## 1. 意图层

手机不是把电脑窗口缩小。菜单栏、工具栏、托盘都不搬过来。颜色和标志必须还是 CopyQ 的。

### 规则

| # | 规则 | 来源 |
|---|------|------|
| M1 | 假如用户在手机上选用 `shared/themes` 里的某个主题文件，那么列表背景、文字、选中背景、选中文字、交替行、编号、编辑区背景、编辑区文字、笔记背景、笔记文字、查找背景、查找文字，分别对应 `bg`、`fg`、`sel_bg`、`sel_fg`、`alt_bg`、`num_fg`、`edit_bg`、`edit_fg`、`notes_bg`、`notes_fg`、`find_bg`、`find_fg`。显示出来的颜色与电脑端对同一个键算出的结果相同。值里如果引用了别的键或写成颜色加减，不能把原文当成颜色名字。手机不另造这些颜色。 | 配色、主题与电脑端一致 |
| M2 | 假如用户还没选主题，那么这些颜色跟随系统调色板，映射方式和电脑端未选择主题文件时相同。不写死一套新的品牌色。 | 同上 |
| M3 | 假如用户看到主屏幕图标、关于页或启动画面上的标志，那么图形就是仓库里的 `src/images/icon.svg` 和已经导出的 png。不重画，不改颜色。 | 标志与电脑端一致 |
| M4 | 假如用户打开手机上的 CopyQ，那么他看到的是竖屏里的历史列表。看不到电脑上的菜单栏、工具栏和多窗口。布局不同不算主题不一致。 | 手机要能用，但不能换成另一套视觉 |
| M5 | 假如一条文字进入历史，那么关掉再打开应用后，它仍在原来的标签页里，相对顺序不变。 | 电脑端会记住历史 |
| M6 | 假如新文字和已有某条完全相同，那么不留下两份，而是把已有那条放到当前标签页最前面。 | 电脑端对相同内容的处理 |
| M7 | 假如用户在应用里新建一条文字，那么它出现在当前标签页最前面。 | 手动加入 |
| M8 | 假如应用正处于前台，系统也允许这次读取，并且系统剪贴板文字变了，那么按 M6 收入当前标签页。假如系统拒绝读取，那么不编造条目，并在界面上说明自动捕获不可用。 | 只做系统允许的捕获 |
| M9 | 假如用户在别的应用里，用系统提供的分享或拷贝入口把文字交给 CopyQ，那么按 M6 收入当前标签页，即使 CopyQ 当时不在前台。这个入口不读取用户没有主动交出的内容。 | 没有后台监听时，这是手机上真正能用的入口 |
| M10 | 假如用户对一条历史执行复制，那么系统剪贴板变成这条文字。CopyQ 不向别的应用注入粘贴。 | 手机系统不允许替用户粘贴 |
| M11 | 假如用户输入查找文字，那么当前标签页只留下正文包含这段文字的条目，大小写按用户输入原样匹配。清空后列表恢复。首次不要求正则。 | 电脑端可以搜历史 |
| M12 | 假如用户编辑一条并确认，那么只有这条的正文改变。假如用户删除一条，那么不要求再次确认，这条从该标签页消失。 | 单条删除与电脑端一样不二次确认 |
| M13 | 假如用户新建、改名或切换标签页，那么条目留在各自的标签页。删除整个标签页前要先确认。取消则该页和里面的条目都还在。确认后该页和里面的条目一起消失。 | 标签页是 CopyQ 的基本结构 |
| M14 | 假如没有指定剪贴板标签页，那么新捕获的文字进入默认页。默认页的名字与电脑端相同，显示时不画出用于快捷键的 `&`。已有配置里指定了别的页，就进入那一页。 | 与电脑端默认页一致 |
| M15 | 假如一个标签页的条目数超过配置里的 `maxitems`，那么丢掉最旧、且没有被钉住的条目。没有这项配置时按 200。超过 100000 时按 100000。钉住尚未在首次做出，所以首次就是丢掉最旧的。 | 电脑端已有的条数上限 |
| M16 | 假如用户在手机备份页填写地址、账号和密码，那么上传、刷新、重置、下载、删除的结果遵守桌面 SPEC 的 R3、R4、R5、R6、R7、R8、R13，错误码也用那一张表。密码不出现在界面和错误详情里。不跟随重定向。不提供忽略证书。 | 同一份 WebDAV 配置同步 |
| M17 | 假如用户下载后取消，那么手机上的配置和历史都保持下载前。假如用户确认，那么这份 zip 替换受管配置；历史目录、状态、锁、日志、隐藏文件、符号链接按桌面 SPEC 的 R12 排除，不进包，也不被包删掉。写入做到一半失败时，受管配置回到恢复前。 | 同一包，同一排除范围 |
| M18 | 假如手机手里没有一份完整的受管配置，用户直接上传，那么先不连接服务器，并说明：电脑恢复这个包时，会删掉电脑上有、而这个包里没有的配置文件。用户看过这句话并确认后才上传。用户拒绝则不产生网络请求。 | 桌面恢复会删除包里没有的受管文件 |
| M19 | 假如恢复成功，那么手机立即改用新配置，或者明确告诉用户需要重新打开。不使用电脑上那套延迟 shell 重启。重新打开没安排成功时，沿用桌面错误码 `RESTART_FAILED` 的文案职责：告诉用户自己打开，不假装已经生效。 | 手机没有 `/bin/sh` 拉起桌面进程这一套 |
| M20 | 假如 M1 到 M19 在 Android 上成立，那么同一条在 iOS 上也成立，反过来也一样。只做完一个系统不算首次完成。 | 两端是同一个产品 |

### 边界

| # | 不做 | 理由 |
|---|---------|------|
| B1 | 不用辅助功能、私有接口、越狱或企业描述文件去后台持续读取剪贴板 | 那是在绕开系统对剪贴板的限制，不是移植 |
| B2 | 不做全局快捷键、托盘菜单、按来源窗口忽略、向其他应用注入粘贴 | 两个手机系统都没有电脑上的这些能力 |
| B3 | 不把 Qt Widgets 的电脑主窗口当作手机界面 | 布局是电脑的。颜色用 M1，导航用 M4 |
| B4 | 不发明第二种配置包、第二种清单字段或另一套错误码 | 桌面 SPEC 和 `docs/schemas/copyq-config-manifest.schema.json` 仍是唯一格式 |
| B5 | 首次不把剪贴板历史放进 WebDAV 包，也不承诺手机历史文件能被电脑端直接打开 | 桌面 SPEC 的 B2。历史同步是另一个产品决定 |
| B6 | 首次不做图片、笔记、标签、钉住、加密、命令、FakeVim、目录同步、脚本服务器、应用锁、正则搜索、防截屏 | 这些在 `mobile/todo.md`，没有首次的「假如…那么…」 |
| B7 | 不把 `upstream/android` 的旧 qmake 空壳算作本产品 | 它没有这套 WebDAV，也没有可用的手机历史 |
| B8 | 不关闭 TLS 校验，不跟随 HTTP 重定向 | 与桌面 SPEC 的 B5 同一理由 |
| B9 | 不新画标志，不增加与主题文件无关的配色 | 用户要求跟电脑端一致 |

### 一致性

| 规则 | 出错时用户看到什么 | 不一致持续 10 分钟会怎样 | 可接受 |
|------|------------------|----------------------|--------|
| M8 M9 | 系统拒绝时有一句说明，没有假条目 | 用户以为在记录，其实没有。必须能看见说明 | 不可以静默 |
| M17 M19 | 成功则已经换上新配置，或写明要重新打开。失败则配置回到恢复前 | 磁盘已是新配置但界面仍是旧的，直到重新打开。必须有文字 | 可以。不能静默，也不能留下半份配置 |
| M18 | 没确认前服务器上看不到新包 | 手机以为传过，电脑没有。确认前请求数为 0 | 不可以先上传再解释 |
| M16 | 认证失败、拒绝重定向都有说明，文字里没有密码 | 用户可能反复用错误密码。秘密不能出现在说明里 | 可以失败。不可以泄密 |

## 2. 数据契约

配置包不在这里定义。清单仍是 [copyq-config-manifest.schema.json](../docs/schemas/copyq-config-manifest.schema.json)：`format` 为 `copyq-config`，`format_version` 为 `1`，多一个字段就算无效。

手机本地历史不是那个包的一部分。结构只允许 [history-store.schema.json](schemas/history-store.schema.json) 里的字段。它必须放在会被配置打包排除的历史目录里。

主题颜色只读 `shared/themes/*.ini` 的键，或按 M2 读系统调色板。本文件不复制色值。`items.css`、`menu.css`、`main_window.css` 是电脑控件样式，不是手机颜色的另一份权威。

## 3. 接口契约

备份页的动作和桌面相同：上传、刷新、重置、下载、删除。地址、账号、密码有一项为空白时，不连接。

不新增错误码。桌面 SPEC 的错误码表继续用。

| 情况 | 使用的结果 | 网络 |
|------|------------|------|
| 残缺配置，用户还没确认上传 | 不上传。说明见 M18。用户拒绝时沿用 `CANCELLED` 的职责：只显示状态，不弹成故障 | 0 次 |
| 残缺配置，用户确认上传 | 之后的失败仍用桌面错误码 | 与桌面同一次上传相同 |
| 系统拒绝读取剪贴板 | 不新增错误码。界面说明自动捕获不可用，历史不变 | 0 次 |
| 恢复已落盘，但没有换成新界面 | `RESTART_FAILED`。文案告诉用户重新打开 | 下载本身已经结束 |
