# ARCH — 手机端架构约束

> **文档类型：权威事实源（仅限技术约束）**
> 行为规则以 [SPEC.md](SPEC.md) 为准。桌面同步模块的依赖方向仍以仓库根目录的 [ARCH.md](../ARCH.md) 为准。不要在这里重写规则句子。

## 1. 技术栈

| 层 | 选型 | 理由 |
|---|------|------|
| 配置包和 WebDAV | 继续用 `src/common` 里的归档、WebDAV 客户端和同步入口 | 格式已经有桌面测试。再写一份 Kotlin 或 Swift 会变成第二种包 |
| 界面 | 一套 Qt Quick 界面，Android 和 iOS 共用 | 两端要满足同一批 M 规则。Qt Widgets 主窗口不是手机界面 |
| 主题 | 读取 `shared/themes/*.ini`，颜色加减沿用桌面已有的求值 | SPEC M1。不在手机里重写一套表达式，也不把 `main_window.css` 套到手机上 |
| 标志 | `src/images/icon.svg` 与同目录 png | SPEC M3。不新增一张重绘的 logo |
| 历史 | 手机自己的本地存储，放在配置打包会排除的历史目录 | 首次不承诺电脑能打开这个文件 |
| 测试 | 现有 `build/copyq-tests` | T2、T3 不需要设备 |
| 构建 | 仓库的 CMake。手机目标等到 T4 再加 | 空目标会看起来像已经移植 |

**新增依赖**：不允许为 zip、HTTP、JSON、主题解析加库。Qt 6 和现有 C++ 够用。

iOS 需要本机 Xcode。没有它就不能把 T6 标成通过。不要用「Qt 文档说支持」代替一次真实编译。

## 2. 目录

T4 之前不创建这些目录。列在这里是为了届时不要散落到别处：

```
mobile/SPEC.md                 已经存在
mobile/schemas/                本地历史的字段，不是配置包
src/common/                    不复制一份手机专用 zip
src/mobile/                    以后放历史存储、主题读取、上传前确认
src/mobile/ui/                 以后放两端共用的 Qt Quick 界面
src/platform/android/          以后放剪贴板与分享，不从 upstream/android 整支合并
src/platform/ios/              以后放剪贴板与分享
```

依赖方向：界面 → 手机历史与主题读取 → 现有同步入口。同步入口继续调用归档和 WebDAV。归档不发网络请求。WebDAV 不写历史目录。手机界面不直接组 zip 字节。

`upstream/android` 只能当参考。那个分支的平台接口是旧的，里面没有这次的备份，也没有 M1–M20。合并它会把 qmake 残骸带进来。

## 3. 命名

| 对象 | 约定 | 不要 |
|------|------|------|
| 错误码 | 继续用桌面的 `SCREAMING_SNAKE` | 不要加 `MOBILE_UPLOAD_BLOCKED` 这类新码 |
| 主题键 | 只用 SPEC M1 的 12 个名字 | 不要发明 `primary`、`accent` |
| 历史 schema | `history-store.schema.json` | 不要把这个文件塞进配置 zip |
| 测试组 | 计划名 `testMobileSync`，以 SPEC 第 5 节最终写下的为准 | 不要塞进 `testConfigSync` 里混着证明两件事 |

## 4. 变化原因

| A | B | A 可以依赖 B？ | 原因是否相同 |
|---|---|---------------|----------------|
| 手机界面 | 主题 ini | 可以读颜色 | 否。布局会变，色值不在手机里改 |
| 手机界面 | WebDAV | 否，只通过现有同步入口 | 否 |
| 上传前确认 | zip 格式 | 确认在调用上传之前 | 否。警告文案和包格式分开变 |
| Android 分享入口 | iOS 分享入口 | 否 | 否。系统入口不同，收入历史的结果必须相同 |
| 手机历史文件 | 电脑条目文件 | 否 | 否。首次不共享这个格式 |

## 5. 禁止

- 不要恢复任何能把同步变回未实现的环境变量开关。
- 不要在日志、错误详情、界面文字里放 WebDAV 密码。
- 不要加「忽略证书」或跟随重定向。
- 不要新建 Android 或 iOS 工程来制造已经移植的外观。工程是 T4 和 T6 的产物，而且要带上 SPEC 里对应的行为。
- 不要用辅助功能或私有剪贴板接口实现后台监听。
- 不要改 `shared/themes` 的色值来迁就手机。手机迁就这些文件。
